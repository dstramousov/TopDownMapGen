# Алгоритм генерации карты

Этот документ описывает общий алгоритм генерации top-down карты. Логика построена как последовательный pipeline: от грубой структуры уровня к проходимости, тактическим слоям, объектам, декору и debug-выводу.

Главная цель генератора — не просто случайно расставить тайлы, а создать карту, которая:

- воспроизводится по seed;
- имеет валидную навигацию;
- содержит читаемую структуру;
- поддерживает тактические зоны;
- не ломается из-за случайного размещения объектов;
- может быть проверена и отлажена через вспомогательные слои.

## Запуск

Базовый запуск генератора из корня проекта:

```bash
python top_down_generator.py --config configs/default.json --out out/generated_map.json
```

Альтернативные профили:

```bash
python top_down_generator.py --config configs/survival.json --out out/survival_map.json
python top_down_generator.py --config configs/timed_breakthrough.json --out out/timed_breakthrough_map.json
```

После установки проекта можно использовать console script:

```bash
generate-world --config configs/default.json --out out/generated_map.json
```

## 1. Общая идея

Генерация карты должна идти от структуры к деталям.

Правильный подход — сначала создать скелет карты:

1. базовую сетку;
2. проходимые и непроходимые области;
3. ключевые точки;
4. маршруты;
5. тактические зоны;
6. игровые объекты;
7. декоративное оформление;
8. debug-слои и экспорт.


---

## 2. Входные данные

На вход генератор получает набор параметров:

- размер карты;
- seed;
- профиль генерации;
- настройки биома или окружения;
- правила размещения объектов;
- параметры плотности препятствий;
- параметры тактических зон;
- настройки экспорта;
- настройки debug-слоёв.

Seed используется для детерминированной генерации. Это значит, что одинаковый seed при одинаковом профиле должен давать одинаковую карту.

---

## 3. Создание базовой сетки

Первый этап — создание двумерного поля фиксированного размера.

На этом этапе каждая ячейка карты получает базовое состояние. Обычно это нейтральная или пустая область, которая позже будет уточняться.

Задача этапа — подготовить рабочую структуру данных, с которой дальше будут работать остальные части генератора.

Готовим корректную основу:

- ширина и высота карты заданы явно;
- все координаты находятся в допустимых границах;
- каждая клетка может быть классифицирована;
- дальнейшие этапы могут безопасно читать и изменять карту.

---

## 4. Первичный layout

После создания сетки формируется общий layout карты.

На этом этапе генератор определяет крупные области:

- открытые пространства;
- плотные зоны;
- потенциальные проходы;
- границы;
- непроходимые участки;
- будущие зоны интереса.

Это ещё не финальная карта, а черновая пространственная структура.

Важно, чтобы layout сразу учитывал будущую игровую логику. Если карта должна быть пригодна для top-down движения, нельзя превращать её в случайную кашу из препятствий. Нужно заранее оставлять место для маршрутов, манёвра и размещения объектов.

---

## 5. Навигационный слой

После первичной разметки создаётся навигационный слой.

Он определяет, какие клетки являются:

- проходимыми;
- непроходимыми;
- условно опасными;
- служебными;
- занятыми крупными объектами.

Навигационный слой нужен не только игроку. Он используется почти всеми последующими этапами:

- проверкой связности;
- размещением объектов;
- выбором стартовой позиции;
- построением маршрутов;
- поиском fallback-точек;
- тактической классификацией;
- debug-визуализацией.

Правило простое: если объект визуально выглядит как препятствие, он должен быть препятствием и в логике. Иначе карта будет врать игроку.

---

## 6. Ключевые точки

Следующий этап — размещение ключевых точек.

К ним могут относиться:

- стартовая позиция;
- точки интереса;
- ресурсные зоны;
- опасные зоны;
- укрытия;
- переходы;
- точки появления врагов;
- служебные fallback-позиции.

Ключевые точки нельзя расставлять полностью случайно. Для каждой точки должны быть ограничения:

- минимальная дистанция от старта;
- максимальная дистанция от важных зон;
- доступность по навигационному слою;
- запрет размещения внутри препятствий;
- запрет слишком плотного скопления;
- соответствие тактическому смыслу области.

Если точка не проходит ограничения, она должна быть отброшена или заменена другой.

---

## 7. Основной маршрут

После размещения ключевых точек генератор формирует основной маршрут или сеть маршрутов.

Для top-down карты это не обязательно один линейный путь. Хороший уровень обычно содержит:

- основное направление движения;
- боковые ответвления;
- обходные пути;
- локальные петли;
- зоны выбора;
- контролируемые тупики с наградой или смыслом.

Карта не должна быть ни коридорной трубой, ни бесформенным полем. Ей нужна читаемая структура, но при этом игрок должен иметь пространство для манёвра.

На этом этапе генератор может:

- соединять ключевые точки путями;
- расширять проходы;
- сглаживать формы;
- добавлять вторичные соединения;
- удалять бессмысленные тупики;
- оставлять полезные тупики под ресурсы или события.

---

## 8. Препятствия и тактическая геометрия

Когда основной маршрут готов, генератор добавляет препятствия и тактические элементы.

Это могут быть:

- стены;
- камни;
- обломки;
- густая растительность;
- укрытия;
- узкие проходы;
- choke points;
- открытые опасные зоны;
- зоны ограниченной видимости.

Главное правило: препятствия должны улучшать геометрию карты, а не ломать её.

После размещения крупных объектов нужно повторно проверить навигацию. Если объект перекрыл важный проход, генератор должен:

- удалить объект;
- перенести объект;
- расширить проход;
- создать обходной маршрут;
- отклонить текущую попытку генерации.

Рандом без проверки здесь плохой вариант. Он может создать карту, которая выглядит нормально на скриншоте, но плохо играется.

---

## 9. Тактическая классификация

После построения геометрии генератор анализирует карту и создаёт тактические слои.

Клетки или области могут получать метки:

- открытая зона;
- укрытие;
- безопасная зона;
- опасная зона;
- узкий проход;
- зона контроля;
- зона обзора;
- зона засады;
- ресурсная область;
- fallback-область.

Эти слои не обязательно видны игроку напрямую. Они нужны для внутренней логики игры.

Например:

- враги могут появляться в зонах засады;
- ресурсы могут размещаться в безопасных или умеренно опасных местах;
- важные объекты не должны появляться там, где игрок их почти наверняка не заметит;
- ИИ может использовать укрытия и зоны контроля;
- debug-слои позволяют понять, почему генератор выбрал конкретную позицию.

Тактическая классификация делает карту не просто набором тайлов, а игровой системой.

---

## 10. Размещение игровых объектов

После тактической классификации размещаются игровые объекты.

К ним могут относиться:

- ресурсы;
- враги;
- интерактивные объекты;
- маркеры событий;
- точки входа и выхода;
- элементы окружения, влияющие на gameplay;
- служебные триггеры.

Размещение объектов должно опираться на уже созданные слои:

- объект не должен появляться вне карты;
- объект не должен появляться внутри непроходимой области;
- объект должен соответствовать тактической зоне;
- важные объекты должны быть достижимы;
- плотность объектов должна быть ограничена;
- объекты не должны конфликтовать друг с другом.

Если объект невозможно разместить по основным правилам, генератор должен использовать fallback-механику.

---

## 11. Fallback-точки

Fallback-точки нужны для безопасного запасного размещения объектов.

Например, генератор хочет поставить ресурс в хорошую ресурсную зону, но все подходящие клетки заняты или недоступны. В таком случае он не должен ставить ресурс куда попало.

Вместо этого используется fallback-логика:

1. найти ближайшую допустимую позицию;
2. проверить её по навигации;
3. проверить конфликт с другими объектами;
4. проверить соответствие минимальным правилам;
5. разместить объект или отказаться от него.

Fallback — это не мусорная корзина. Это контролируемый запасной механизм.

Если fallback-точки используются слишком часто, это сигнал, что основные правила генерации плохие или слишком жёсткие.

---

## 12. Декоративное наполнение

Когда структура, маршруты, препятствия и объекты готовы, генератор добавляет декор.

Декор может включать:

- вариации поверхности;
- мелкие детали;
- растительность;
- мусор;
- следы;
- визуальные переходы;
- декоративные объекты.

Декоративные элементы должны делиться на две группы:

1. чисто визуальные;
2. влияющие на gameplay.

Чисто визуальный декор не должен менять проходимость. Если маленький декоративный объект внезапно блокирует игрока, это плохое решение. Игрок должен понимать карту глазами.

Gameplay-декор, наоборот, должен явно отражаться в логике карты: если куст скрывает обзор, если камень блокирует движение, если болото замедляет — это должно быть зафиксировано в соответствующих слоях.

---

## 13. Валидация

После генерации выполняется проверка карты.

Минимальная валидация должна проверять:

- размеры карты;
- наличие стартовой точки;
- наличие обязательных объектов;
- связность ключевых областей;
- корректность навигационного слоя;
- отсутствие объектов вне границ;
- отсутствие объектов внутри непроходимых клеток;
- отсутствие критических пересечений;
- достаточное количество проходов;
- достаточное количество ресурсов;
- корректность тактических слоёв;
- корректность fallback-точек.

Если карта не проходит проверку, генератор может:

- локально исправить проблему;
- удалить конфликтный объект;
- перестроить часть карты;
- отклонить результат;
- повторить генерацию с ограниченным числом попыток.

Нельзя допускать бесконечные попытки генерации. У генератора должен быть лимит попыток и понятная ошибка, если валидную карту создать не удалось.

---

## 14. Debug-слои

Для разработки генератор должен уметь сохранять debug-слои.

Полезные debug-слои:

- навигация;
- препятствия;
- ключевые точки;
- основной маршрут;
- зоны интереса;
- тактическая классификация;
- fallback-точки;
- размещённые объекты;
- маски плотности;
- причины отклонения позиций.

Debug-слои не нужны игроку, но они критичны для разработки.

Без них генератор превращается в чёрный ящик. Если карта плохая, непонятно почему. С debug-слоями можно быстро увидеть, где именно сломалась логика.

---

## 15. Экспорт

Финальный этап — экспорт карты.

Генератор сохраняет результат в формате, который может использовать игра или редактор.

Возможные выходные данные:

- основная карта;
- TMX-файл;
- JSON-описание;
- manifest;
- debug-изображения;
- preview-картинка;
- служебная информация о seed;
- отчёт валидации.

Экспорт должен быть воспроизводимым. Если карта была создана по конкретному seed, этот seed должен сохраняться рядом с результатом.

Это позволит повторить генерацию и проверить проблемный случай.

---

## 16. Общий pipeline

Упрощённо алгоритм выглядит так:

```text
1. Прочитать профиль генерации.
2. Инициализировать RNG по seed.
3. Создать базовую сетку карты.
4. Сформировать первичный layout.
5. Создать навигационный слой.
6. Разместить ключевые точки.
7. Построить основной маршрут.
8. Добавить препятствия и тактическую геометрию.
9. Проверить связность карты.
10. Выполнить тактическую классификацию.
11. Разместить игровые объекты.
12. Использовать fallback-точки при необходимости.
13. Добавить декоративные элементы.
14. Провести полную валидацию.
15. Сохранить карту и debug-слои.
16. Сформировать отчёт генерации.
